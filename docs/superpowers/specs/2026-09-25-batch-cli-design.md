# 배치 번역 CLI 설계 (방향 전환)

- 작성일: 2026-09-25
- 상태: **대체됨** — 2026-09-25에 BallonsTranslator 래퍼 방향으로 전환(`2026-09-25-bt-wrapper-design.md`).
- 관계: `2026-09-25-manga-viewer-design.md`(실시간 뷰어 설계)를 **대체**한다. 그 문서의 번역 파이프라인(5장)과
  보안·테스트 원칙은 계속 유효하지만, 뷰어·웹 UI·설치 파일·첫 실행 마법사는 보류한다.

## 1. 목표

A 폴더의 일본 만화 이미지를 읽어 번역하고, 말풍선을 한국어로 덮어 그린 이미지를 B 폴더에 저장하는 **명령줄 배치 도구**.

- 최종 사용자는 개발자가 아닌 친구들도 포함하지만, **이번 단계는 명령어로 실행하는 최소 구현**이다.
  드래그 앤 드롭 실행, 설치 스크립트, 모델 자동 다운로드는 다음 단계에서 덧붙인다.
- 대상 환경은 기존과 같다: Windows 10/11, NVIDIA RTX 30 시리즈 이상. 빌드·실행·테스트는 네이티브 Windows에서 한다(WSL·Docker 미사용).

## 2. 사용법

```
manga-viewer translate <A폴더> <B폴더> --llama-server <exe> --model <gguf>
    [--mmproj <gguf> --with-image] [--glossary <toml>] [--font <ttf>] [--ctx-size N] [--no-think]
```

- A 폴더 바로 아래의 이미지(`.jpg .jpeg .png .webp .bmp`)를 파일 이름 자연 정렬 순서로 처리한다. 하위 폴더는 보지 않는다.
- 결과는 B 폴더에 `<원본 이름>.png`로 저장한다. B가 없으면 만든다. A와 B가 같으면 거부한다.
- 페이지마다 진행 상황을 한국어로 출력하고, 끝나면 저장·건너뜀·실패 말풍선 수를 요약한다.
- 종료 코드: 모든 페이지 성공 0, 건너뛴 페이지가 있으면 1, 입력 오류 2.

## 3. 처리 흐름

1. **비전**: 기존 `Vision`(mokuro: comic-text-detector + manga-ocr)으로 말풍선 박스, 일본어 원문, 배경색을 얻는다.
2. **번역**: 기존 `Translator`. 직전 2페이지(대사가 있는 페이지만)를 문맥으로, 용어집의 해당 항목, `--with-image`면 페이지 이미지를 참고 자료로 넣는다. llama-server는 `--no-think`로 추론 모드를 끄는 것을 권장한다.
3. **렌더링** (신규 `render.py`):
   - 번역이 있는 말풍선마다 박스를 `bg_color`로 칠한다.
   - 세로로 긴 박스(높이/너비 > 2)는 좌우로 1.5배까지 넓힌다(이미지 경계 안).
   - 한국어를 가로쓰기로, 박스 안에 들어가는 가장 큰 글자 크기(10~72pt)를 이진 탐색으로 찾아 가운데 정렬로 그린다. 공백 단위 줄바꿈, 한 단어가 넘치면 글자 단위 줄바꿈.
   - 글자색은 배경 밝기에 따라 검정/흰색.
   - 폰트 기본값은 `C:\Windows\Fonts\malgun.ttf`(맑은 고딕), `--font`로 변경.
   - 번역에 실패한 말풍선은 원문을 그대로 둔다.
4. **저장**: 페이지를 처리하는 즉시 저장한다(중간에 중단돼도 앞 페이지 결과는 남는다).

## 4. 오류 처리

| 상황 | 처리 |
|---|---|
| A 폴더 없음, 이미지 없음, llama-server·모델·mmproj·용어집·폰트 파일 없음 | 한국어 안내 출력, 종료 코드 2 |
| llama-server 기동 실패 | "LLM 서버를 시작하지 못했습니다: …" 출력, 종료 코드 2, 프로세스 정리 |
| 이미지 읽기·검출 실패 | 그 페이지 건너뜀, 이유 출력, 다음 페이지 계속 |
| 결과 저장 실패 | 그 페이지 건너뜀으로 집계 |
| 말풍선 번역 실패 (재요청 후) | 원문 유지 |

## 5. 전역 수정 (최종 리뷰 반영)

- llama-server 통신(`/health`, 채팅)은 시스템 프록시를 쓰지 않는다(`trust_env=False`).
- 콘솔 출력은 UTF-8로 재설정해 cp949 환경에서 일본어 파일 이름을 출력해도 중단되지 않는다.
- 무거운 의존성(torch, mokuro)은 `Vision` 생성 시점에만 불러온다. 이를 검사하는 테스트를 둔다.

## 6. 보류 (다음 단계)

- 드래그 앤 드롭 실행(바탕화면 아이콘), 출력 폴더 자동 이름(`<A>_번역`)
- 하위 폴더 재귀 처리, ZIP/CBZ 입력
- 설치 스크립트, 모델 자동 다운로드, 기본 모델 선택
- 인페인팅
- 멀티모달 모델 단독 방식(OCR 제거): 진행 중인 실험 결과에 따라 1단계만 교체한다.
- 프롬프트·스키마 강화(재요청 시 같은 페이지 문맥, id enum): 기본 모델 확정 후.
