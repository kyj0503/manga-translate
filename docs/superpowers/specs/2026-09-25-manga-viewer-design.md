# manga-viewer 설계 문서

- 작성일: 2026-09-25
- 상태: 사용자 검토 대기

## 1. 목표

일본 만화를 읽는 한국어 사용자를 위한 **로컬 LLM 기반 실시간 번역 만화 뷰어**.
로컬에 저장된 만화를 크롬에서 읽으면, 로컬 GPU에서 말풍선을 검출·OCR·번역하여
한국어 오버레이를 원본 말풍선 위에 표시한다. 외부 API나 인터넷 연결 없이 동작한다
(최초 설치 시 다운로드 제외).

### 대상 환경

- Windows 10/11
- NVIDIA RTX 30 시리즈 이상, **VRAM 12GB 이상**
- 브라우저: Chrome (Chromium 계열이면 동작하지만 Chrome만 공식 지원)

### 범위에서 제외 (YAGNI)

- 인페인팅 기반 완전 식자
- 화면 캡처 번역 (웹 만화 사이트 등)
- NVIDIA 이외 GPU, VRAM 12GB 미만
- 원격 접속 / 다중 사용자
- 말풍선 단위 스트리밍 표시
- OCR 결과 수동 편집

## 2. 사용 흐름

1. **설치 (1회)**: `setup.ps1` 실행
   - `nvidia-smi`로 GPU·드라이버·VRAM 확인. VRAM 12GB 미만이면 안내 후 중단.
   - `uv` 설치 → `uv sync`로 Python, PyTorch(CUDA), 의존성 설치.
   - 라이브러리 루트 폴더를 물어 `config.toml` 생성.
   - `manga-viewer setup` 호출 → `manifest.toml`에 정의된 항목 다운로드
     (llama.cpp CUDA 빌드, 검출·OCR 모델, 번역 GGUF 모델, 한국어 폰트).
     체크섬 검증, 이어받기 지원. 이미 받은 항목은 건너뛴다.
2. **실행**: `manga-viewer serve`
   - 터미널 창 하나에 상주. llama-server 기동 → 모델 로드 → 웹 서버 시작 → 크롬 탭 자동 오픈.
   - 진행 로그 출력 (예: `p.12 번역 완료 1.8s`).
3. **읽기**: 크롬에서 라이브러리 탐색 후 책을 열어 읽는다.
4. **종료**: 터미널 창을 닫거나 Ctrl+C. 관련 프로세스는 모두 종료되고 크롬은 유지된다.

## 3. 아키텍처

```
┌─ manga-viewer serve (Python 프로세스, 터미널 1개) ────────────┐
│  웹 서버 (FastAPI + uvicorn, 127.0.0.1 바인딩)                 │
│   ├ 정적 웹 UI (라이브러리 / 읽기 화면)                         │
│   ├ REST API (폴더 목록, 페이지 이미지, 썸네일, 번역, 용어집)    │
│   └ WebSocket (페이지 번역 완료·상태 푸시)                       │
│  스케줄러: 현재 페이지 최우선, 다음 N장 프리페치, 이동 시 취소   │
│  비전 워커 (PyTorch, GPU): 검출 → OCR → 읽기 순서 정렬         │
│  LLM 워커: llama-server에 페이지 단위 번역 요청                 │
│  캐시 (SQLite)                                                  │
└──────────┬─────────────────────────────────────────────────┘
           │ HTTP (OpenAI 호환 API, localhost)
     llama-server.exe  ← Job Object(KILL_ON_JOB_CLOSE)로 수명 결합
```

### 기술 스택

| 영역 | 선택 |
|---|---|
| 언어/환경 | Python, `uv` |
| 웹 서버 | FastAPI + uvicorn |
| 텍스트 검출 | comic-text-detector (PyTorch) |
| OCR | manga-ocr (PyTorch, transformers) |
| LLM 런타임 | llama.cpp `llama-server.exe` (CUDA 빌드), 앱이 자식 프로세스로 관리 |
| 번역 모델 | 12~14B급 GGUF Q4_K_M. 후보: Gemma 3 12B, Qwen3 14B. `manga-viewer bench`로 측정 후 확정 |
| 캐시 | SQLite |
| 프론트엔드 | 빌드 도구 없는 순수 HTML/CSS/JS |
| 폰트 | Noto Sans KR 등 OFL 라이선스 한국어 폰트 |

## 4. 프로세스 수명 관리

- `serve` 시작 시 Job Object를 생성하고 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`를 설정한다.
- llama-server 프로세스**만** Job에 할당한다. Python 프로세스가 어떤 이유로든 종료되면
  (창 닫기, Ctrl+C, 작업 관리자 강제 종료) Job 핸들이 닫혀 OS가 llama-server를 종료한다.
- 크롬은 `webbrowser.open(url)`로 탭만 열고 Job에 넣지 않는다. 서버 종료가 크롬에 영향을 주지 않는다.
- 콘솔 종료 이벤트(`SetConsoleCtrlHandler`: Ctrl+C, 창 닫기)를 받으면 대기 작업을 취소하고
  SQLite를 닫은 뒤 종료한다. 창 닫기는 약 5초 제한이 있으므로 정리 작업은 짧게 유지한다.
- 브라우저는 WebSocket 연결이 끊기면 "번역 서버가 종료되었습니다" 배너를 표시한다.
  이미 받은 오버레이는 계속 볼 수 있다.

## 5. 번역 파이프라인

### 흐름

1. 브라우저가 페이지 N을 연다 → 번역 결과 요청.
   - 캐시 적중: 즉시 반환.
   - 미스: 원본 이미지를 먼저 표시하고 "번역 중" 상태 표시. 완료 시 WebSocket 알림을 받아 오버레이를 그린다.
2. 스케줄러는 N을 최우선으로, 이어 N+1 ~ N+`prefetch`(기본 3)를 큐에 넣는다.
   다른 페이지로 크게 이동하면 해당 책의 대기 작업을 취소한다.
3. **비전 단계**: 검출 → 블록별 OCR(배치) → 읽기 순서 정렬 →
   `[{id, bbox, vertical, bg_color, ja}]`. 목표 1초 미만/페이지.
   `bg_color`는 bbox 가장자리 픽셀의 중앙값.
4. **LLM 단계**: 페이지당 1회 호출로 번역.
5. 비전 단계와 LLM 단계는 별도 워커로 병행한다 (LLM이 N을 번역하는 동안 비전이 N+1 처리).
   llama-server는 `--parallel 1`로 운용한다.

### LLM 요청

- 입력
  - 용어집 중 이번 페이지 원문에 등장하는 항목
  - 직전 2페이지의 (원문, 번역) 쌍. 캐시에 없으면 생략
  - 이번 페이지 말풍선 목록 `[{id, ja}]`
- 출력: `response_format`에 JSON 스키마를 지정한다 → `{"translations": [{"id": ..., "ko": ...}]}`
- 시스템 프롬프트: 캐릭터 말투(반말·존댓말) 유지, 자연스러운 한국어 구어체, 효과음은 짧게 의역,
  용어집 준수.
- temperature 약 0.3.

### 속도 목표

- RTX 3060 12GB, 12B Q4 기준 약 30~40 tok/s → 말풍선 10개 페이지 약 8~12초 (추정).
- 첫 페이지만 대기하고, 이후 순차 읽기에서는 프리페치로 대기가 없는 것을 목표로 한다.
- 실측은 `manga-viewer bench`로 수행한다.

### 캐시

| 종류 | 키 |
|---|---|
| 파일 식별 | 경로 + 크기 + 수정 시각 |
| OCR 결과 | 파일 키 + 페이지 인덱스 + 비전 파이프라인 버전 |
| 번역 결과 | OCR 결과 해시 + LLM 모델 id + 용어집 해시 + 프롬프트 버전 |
| 썸네일 | 파일 키 |
| 읽은 위치 | 책 경로 |

OCR과 번역을 분리 저장하므로 용어집·프롬프트·모델을 바꾸면 번역만 다시 한다.

### 오류 처리

| 상황 | 처리 |
|---|---|
| 응답에 일부 id 누락 | 누락분만 모아 1회 재요청 |
| 재요청도 실패 | 해당 말풍선은 원문 표시 + ⚠ 마크 |
| llama-server 무응답·크래시 | 헬스체크로 감지 → 재시작 → 진행 중 작업 재큐. 터미널 경고 로그 |
| 이미지 디코딩 실패 | 페이지 오류 배지, 다음 페이지 계속 |
| 텍스트 미검출 | 정상 결과(빈 오버레이)로 캐시 |

## 6. 웹 UI

### 라이브러리 화면

- `config.toml`의 라이브러리 루트부터 탐색한다.
- 항목: 하위 폴더, 책(이미지가 들어 있는 폴더 또는 `.zip`/`.cbz`).
- 파일 이름은 자연 정렬한다 (`2.jpg` < `10.jpg`).
- 책마다 첫 페이지 썸네일을 표시한다 (서버에서 축소 JPEG 생성 후 캐시).
- 책마다 마지막으로 읽은 페이지를 기억해 "이어 읽기"를 제공한다.

### 읽기 화면

- 기본 우→좌 넘김. 한 페이지 / 양면 보기 전환.
- 단축키

| 키 | 동작 |
|---|---|
| `←` / `Space` | 다음 페이지 |
| `→` | 이전 페이지 |
| `T` | 원본/번역 토글 |
| `D` | 양면 보기 토글 |
| `F` | 화면 맞춤 전환 (너비/높이) |
| `G` | 용어집 패널 |
| `Esc` | 라이브러리로 |

- 마우스: 화면 왼쪽 절반 클릭은 다음 페이지, 오른쪽 절반은 이전 페이지.
- 오버레이
  - 말풍선마다 이미지 좌표에 맞춰 절대 위치 `<div>`를 둔다. 배경은 `bg_color`.
  - 한국어는 가로쓰기. 글자 크기를 이진 탐색으로 박스에 맞춘다. 세로쓰기 말풍선처럼 좁은 박스는
    필요하면 좌우로 제한된 비율만큼 넓힌다.
  - 마우스를 올리면 원문 일본어를 툴팁으로 표시한다. 번역 텍스트는 선택·복사할 수 있다.
- 상태 표시: 현재 페이지 상태(번역 중, 완료, 오류)와 프리페치 진행(예: `+3`).

### 용어집

- 단위: 시리즈. 책이 들어 있는 상위 폴더를 시리즈로 본다.
- 저장: `%LOCALAPPDATA%\manga-viewer\glossaries\`. 사용자 만화 폴더에는 쓰지 않는다.
- `G` 패널에서 (원문, 번역, 메모) 표를 편집한다. 저장하면 해당 시리즈의 번역 캐시 키가 바뀌어
  현재 페이지부터 다시 번역된다.

## 7. 설정

`%LOCALAPPDATA%\manga-viewer\config.toml`

```toml
library_roots = ["D:\\Manga"]
port = 8765
prefetch = 3
model = "gemma-3-12b-q4_k_m"   # manifest.toml의 모델 id
```

런타임과 모델 파일은 `%LOCALAPPDATA%\manga-viewer\` 아래에 둔다.

## 8. 보안

- 웹 서버는 `127.0.0.1`에만 바인딩한다.
- 모든 경로 파라미터는 정규화한 뒤 라이브러리 루트의 하위인지 검사한다 (`..`, 심볼릭 링크, 절대 경로 거부).
- ZIP 엔트리 이름도 같은 방식으로 검증한다 (zip slip 방지). 압축은 메모리에서만 읽고 디스크에 풀지 않는다.

## 9. 테스트

| 대상 | 방법 |
|---|---|
| `source` | 자연 정렬, ZIP/CBZ 읽기, 경로 조작 차단 |
| `order` | 합성 bbox로 읽기 순서 검증 |
| `translate` | 프롬프트 구성, JSON 파싱, 누락 id 재요청 (가짜 LLM 서버) |
| `cache` | 키 계산, 용어집 변경 시 무효화 |
| `scheduler` | 우선순위, 취소, 2단계 병행 |
| 프로세스 수명 | 더미 자식을 Job에 넣고 부모를 강제 종료 → 자식 종료 확인 (Windows 통합 테스트) |
| 웹 UI | 가짜 파이프라인을 붙인 Playwright 스모크 1개: 라이브러리 → 읽기 → 오버레이 → `T` 토글 |
| 품질·속도 | `manga-viewer bench <폴더>`: 페이지당 소요 시간과 번역 결과를 HTML로 출력해 사람이 검토. 샘플 만화는 저장소에 넣지 않는다 |

## 10. 결정 대기 항목

- 기본 번역 모델: Gemma 3 12B와 Qwen3 14B(또는 그 시점의 동급 최신 모델)를 `bench`로 비교해 확정한다.
  구현 계획의 첫 단계로 둔다.
