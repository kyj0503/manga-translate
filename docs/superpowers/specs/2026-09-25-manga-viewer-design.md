# manga-viewer 설계 문서

- 작성일: 2026-09-25
- 상태: 사용자 검토 대기

## 1. 목표

일본 만화를 읽는 한국어 사용자를 위한 **로컬 LLM 기반 실시간 번역 만화 뷰어**.
로컬에 저장된 만화를 앱에서 열면 로컬 GPU로 말풍선을 검출·OCR·번역해서
한국어 오버레이를 원본 말풍선 위에 표시한다. 최초 설치 때 파일을 내려받은 뒤에는
외부 API나 인터넷 연결 없이 동작한다.

**대상 사용자는 개발자가 아닌 일반인이다.** 사용자는 설치 파일을 더블클릭하고, 앱 창 안에서 모든 것을 한다.
사용자 눈에 터미널, 명령어, 설정 파일이 보여서는 안 된다.

### 대상 환경

- Windows 10/11 (WebView2 런타임 필요. Windows 11에는 기본 포함, Windows 10은 설치 파일이 확인 후 설치)
- NVIDIA RTX 30 시리즈 이상, **VRAM 12GB 이상**
- 여유 디스크 공간 약 15GB

### 범위에서 제외 (YAGNI)

- 인페인팅 기반 완전 식자
- 화면 캡처 번역 (웹 만화 사이트 등)
- NVIDIA 이외 GPU, VRAM 12GB 미만
- 원격 접속, 다중 사용자
- 말풍선 단위 스트리밍 표시
- OCR 결과 수동 편집
- 자동 업데이트 (새 버전 알림만 제공)
- 코드 서명 (SmartScreen 경고는 안내 이미지로 대응)

## 2. 사용 흐름

1. **설치**: `manga-viewer-setup.exe` 더블클릭 → "다음 → 설치".
   - Inno Setup 설치 파일. 관리자 권한 없이 `%LOCALAPPDATA%\Programs\manga-viewer`에 설치한다.
   - 시작 메뉴와 바탕화면에 바로가기를 만든다.
   - WebView2 런타임이 없으면 설치한다.
2. **첫 실행 마법사** (앱 창 안)
   1. 환경 검사: NVIDIA GPU, 드라이버 버전, VRAM 12GB 이상, 디스크 여유 공간.
      실패하면 이유와 해결 방법을 쉬운 말로 보여주고 진행을 막는다.
   2. 만화 폴더 선택 (Windows 폴더 선택 창).
   3. 다운로드·설치: PyTorch(CUDA) 등 무거운 의존성, llama.cpp CUDA 빌드, 검출·OCR 모델,
      번역 GGUF 모델. 단계별 진행률과 남은 시간을 표시한다. 중간에 끊기거나 앱을 닫아도 다음 실행 때 이어서 진행한다.
3. **실행**: 바로가기를 누르면 앱 창 하나가 뜬다. 콘솔 창은 없다.
   라이브러리 화면에서 책을 골라 읽는다.
4. **종료**: 앱 창을 닫으면 관련 프로세스가 모두 종료된다.

## 3. 아키텍처

```
┌─ 앱 프로세스 (pythonw.exe -m manga_viewer) ────────────────────┐
│  pywebview 창 (WebView2) ── 내부 웹 UI 로드                     │
│  웹 서버 (FastAPI + uvicorn, 127.0.0.1, 빈 포트 자동 선택)       │
│   ├ 정적 웹 UI (마법사, 라이브러리, 읽기, 설정)                   │
│   ├ REST API (폴더 목록, 페이지 이미지, 썸네일, 번역, 용어집, 설정)│
│   └ WebSocket (번역 완료, 다운로드 진행률, 상태 푸시)              │
│  스케줄러: 현재 페이지 최우선, 다음 N장 프리페치, 이동 시 취소     │
│  비전 워커 (PyTorch, GPU): 검출 → OCR → 읽기 순서 정렬           │
│  LLM 워커: llama-server에 페이지 단위 번역 요청                   │
│  캐시 (SQLite)                                                    │
└──────────┬──────────────────────────────────────────────────┘
           │ HTTP (OpenAI 호환 API, localhost)
     llama-server.exe  ← Job Object(KILL_ON_JOB_CLOSE)로 수명 결합
```

### 배포 구성

설치 파일은 수십 MB 수준으로 작게 유지하고, 무거운 파일은 첫 실행 마법사가 내려받는다.
PyInstaller로 exe 하나에 묶는 방식은 백신 오탐과 용량 문제 때문에 쓰지 않는다.

| 구성 요소 | 위치 | 제공 방식 |
|---|---|---|
| 포터블 Python + 가벼운 의존성이 설치된 venv (pywebview, FastAPI 등) | 설치 폴더 `runtime\` | 설치 파일에 포함 (빌드 스크립트가 `uv`로 생성) |
| 앱 소스, 웹 UI, 한국어 폰트 | 설치 폴더 | 설치 파일에 포함 |
| `uv.exe` | 설치 폴더 | 설치 파일에 포함 |
| PyTorch(CUDA), manga-ocr 등 무거운 의존성 | 같은 venv | 마법사가 `uv pip install`로 설치 |
| llama-server CUDA 빌드, 검출·OCR 모델, GGUF 모델 | `%LOCALAPPDATA%\manga-viewer\` | 마법사가 `manifest.toml` 기준으로 다운로드 |

- 바로가기 대상은 `runtime\pythonw.exe -m manga_viewer`이다. 별도 런처 exe는 만들지 않는다.
- 무거운 의존성은 import를 지연한다. 마법사 단계에서는 PyTorch 없이 앱이 떠야 한다.
- 다운로드 항목은 체크섬으로 검증하고 이어받기를 지원한다.

### 기술 스택

| 영역 | 선택 |
|---|---|
| 언어/환경 | Python, `uv` (빌드와 마법사 내부에서만 사용) |
| 앱 창 | pywebview (WebView2 백엔드) |
| 웹 서버 | FastAPI + uvicorn |

| 이미지 참고 (실험) | 같은 모델의 mmproj를 `--mmproj`로 올리고 페이지 이미지를 번역 참고 자료로 전달. 박스와 원문은 항상 검출기·OCR에서 얻음. 사용 여부는 `bench`로 결정 |

## 4. 프로세스 수명 관리

- **단일 인스턴스**: 이름 있는 뮤텍스로 중복 실행을 막는다. 이미 실행 중이면 기존 창을 앞으로 가져오고 새 프로세스는 종료한다.
- **llama-server 결합**: 앱 시작 시 Job Object를 만들고 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`를 설정한 뒤
  llama-server 프로세스만 할당한다. 앱 프로세스가 어떤 이유로든 종료되면(창 닫기, 크래시, 작업 관리자 강제 종료)
  OS가 llama-server를 종료한다.
- **정상 종료**: 창이 닫히면 대기 작업을 취소하고 SQLite를 닫은 뒤 서버와 프로세스를 종료한다.
- **다운로드 중 종료**: 받던 파일은 부분 파일로 남기고, 다음 실행 때 마법사가 이어서 진행한다.

## 5. 번역 파이프라인

### 흐름

1. 읽기 화면이 페이지 N을 연다 → 번역 결과 요청.
   - 캐시 적중: 즉시 반환.
   - 미스: 원본 이미지를 먼저 표시하고 "번역 중" 상태 표시. 완료 시 WebSocket 알림을 받아 오버레이를 그린다.
2. 스케줄러는 N을 최우선으로, 이어 N+1 ~ N+`prefetch`(기본 3)를 큐에 넣는다.
   다른 페이지로 크게 이동하면 해당 책의 대기 작업을 취소한다.
3. **비전 단계**: 검출 → 블록별 OCR(배치) → 읽기 순서 정렬 →
   `[{id, bbox, vertical, bg_color, ja}]`. 목표 1초 미만/페이지.
   `bg_color`는 bbox 가장자리 픽셀의 중앙값.
4. **LLM 단계**: 페이지당 1회 호출로 번역.
5. 비전 단계와 LLM 단계는 별도 워커로 병행한다 (LLM이 N을 번역하는 동안 비전이 N+1 처리).
   llama-server는 `--parallel 1`로 운용한다.

### LLM 요청

- 입력
  - 용어집 중 이번 페이지 원문에 등장하는 항목
  - 직전 2페이지의 (원문, 번역) 쌍. 캐시에 없으면 생략
  - 이번 페이지 말풍선 목록 `[{id, ja}]`
- 출력: `response_format`에 JSON 스키마를 지정한다 → `{"translations": [{"id": ..., "ko": ...}]}`
- 시스템 프롬프트: 캐릭터 말투(반말·존댓말) 유지, 자연스러운 한국어 구어체, 효과음은 짧게 의역,
  용어집 준수.
- temperature 약 0.3.

### 속도 목표

- RTX 3060 12GB, 12B Q4 기준 약 30~40 tok/s → 말풍선 10개 페이지 약 8~12초 (추정).
- 첫 페이지만 대기하고, 이후 순차 읽기에서는 프리페치로 대기가 없는 것을 목표로 한다.
- 실측은 `bench`로 수행한다.

### 캐시

| 종류 | 키 |
|---|---|
| 파일 식별 | 경로 + 크기 + 수정 시각 |
| OCR 결과 | 파일 키 + 페이지 인덱스 + 비전 파이프라인 버전 |
| 번역 결과 | OCR 결과 해시 + LLM 모델 id + 용어집 해시 + 프롬프트 버전 |
| 썸네일 | 파일 키 |
| 읽은 위치 | 책 경로 |

OCR과 번역을 분리 저장하므로 용어집·프롬프트·모델을 바꾸면 번역만 다시 한다.

### 오류 처리

| 상황 | 처리 |
|---|---|
| 응답에 일부 id 누락 | 누락분만 모아 1회 재요청 |
| 재요청도 실패 | 해당 말풍선은 원문 표시 + ⚠ 마크 |
| llama-server 무응답·크래시 | 헬스체크로 감지 → 재시작 → 진행 중 작업 재큐. 반복 실패하면 화면에 안내 |
| 이미지 디코딩 실패 | 페이지 오류 배지, 다음 페이지 계속 |
| 텍스트 미검출 | 정상 결과(빈 오버레이)로 캐시 |

## 6. 화면 (웹 UI)

모든 화면은 앱 창 안의 웹 UI로 구현한다. 사용자에게 보이는 문구는 전부 쉬운 한국어로 쓴다.

### 첫 실행 마법사

- 환경 검사 결과를 항목별 ✓/✗로 보여준다. ✗에는 원인과 해결 방법을 붙인다.
  - 예: "그래픽 드라이버가 오래됐어요. [NVIDIA 드라이버 다운로드 페이지 열기]"
  - 예: "그래픽카드 메모리가 8GB예요. 이 프로그램은 12GB 이상이 필요해요."
- 만화 폴더 선택 버튼.
- 다운로드 단계: 항목별 크기, 전체 진행률, 남은 시간. 실패하면 "다시 시도" 버튼.

### 라이브러리 화면

- 등록한 만화 폴더부터 탐색한다.
- 항목: 하위 폴더, 책(이미지가 들어 있는 폴더 또는 `.zip`/`.cbz`).
- 파일 이름은 자연 정렬한다 (`2.jpg` < `10.jpg`).
- 책마다 첫 페이지 썸네일을 표시한다 (서버에서 축소 JPEG 생성 후 캐시).
- 책마다 마지막으로 읽은 페이지를 기억해 "이어 읽기"를 제공한다.

### 읽기 화면

- 기본 우→좌 넘김. 한 페이지 / 양면 보기 전환.
- 단축키

| 키 | 동작 |
|---|---|
| `←` / `Space` | 다음 페이지 |
| `→` | 이전 페이지 |
| `T` | 원본/번역 토글 |
| `D` | 양면 보기 토글 |
| `F` | 화면 맞춤 전환 (너비/높이) |
| `F11` | 전체 화면 |
| `G` | 용어집 패널 |
| `Esc` | 라이브러리로 |

- 마우스: 화면 왼쪽 절반 클릭은 다음 페이지, 오른쪽 절반은 이전 페이지.
  단축키는 화면의 도움말(`?`)로 확인할 수 있다.
- 오버레이
  - 말풍선마다 이미지 좌표에 맞춰 절대 위치 `<div>`를 둔다. 배경은 `bg_color`.
  - 한국어는 가로쓰기. 글자 크기를 이진 탐색으로 박스에 맞춘다. 세로쓰기 말풍선처럼 좁은 박스는
    필요하면 좌우로 제한된 비율만큼 넓힌다.
  - 마우스를 올리면 원문 일본어를 툴팁으로 표시한다. 번역 텍스트는 선택·복사할 수 있다.
- 상태 표시: 현재 페이지 상태(번역 중, 완료, 오류)와 프리페치 진행(예: `+3`).

### 용어집

- 단위: 시리즈. 책이 들어 있는 상위 폴더를 시리즈로 본다.
- 저장: `%LOCALAPPDATA%\manga-viewer\glossaries\`. 사용자 만화 폴더에는 쓰지 않는다.
- `G` 패널에서 (원문, 번역, 메모) 표를 편집한다. 저장하면 해당 시리즈의 번역 캐시 키가 바뀌어
  현재 페이지부터 다시 번역된다.

### 설정 화면

- 만화 폴더 추가·삭제 (Windows 폴더 선택 창)
- 미리 번역할 페이지 수
- 번역 모델 선택 (manifest에 있는 모델 중에서. 바꾸면 필요한 파일을 내려받는다)
- "로그 폴더 열기", "캐시 비우기" 버튼
- 앱 버전과 새 버전 알림 (시작 시 GitHub Releases 확인, 새 버전이 있으면 다운로드 페이지 링크)

## 7. 파일 위치

| 경로 | 내용 |
|---|---|
| `%LOCALAPPDATA%\Programs\manga-viewer\` | 앱 소스, 웹 UI, 폰트, `runtime\`(Python venv), `uv.exe` |

```toml
library_roots = ["D:\\Manga"]
prefetch = 3
model = "gemma-4-e2b-q4_k_m"   # manifest.toml의 모델 id
```

제거 시 설치 폴더는 삭제하고, 데이터 폴더(모델 약 10GB 포함)를 함께 지울지 묻는다.

## 8. 보안

- 웹 서버는 `127.0.0.1`에만 바인딩한다.
- 앱 시작 시 무작위 세션 토큰을 만들어 창에 넘기고, 모든 API와 WebSocket 요청에서 검사한다.
  `Host` 헤더도 `127.0.0.1:<포트>`인지 확인한다. 같은 PC의 다른 웹 페이지가 로컬 서버에 접근하는 것을 막기 위함이다.
- 모든 경로 파라미터는 정규화한 뒤 라이브러리 폴더의 하위인지 검사한다 (`..`, 심볼릭 링크, 절대 경로 거부).
- ZIP 엔트리 이름도 같은 방식으로 검증한다 (zip slip 방지). 압축은 메모리에서만 읽고 디스크에 풀지 않는다.
- 다운로드는 `manifest.toml`에 적힌 URL과 SHA-256이 일치할 때만 사용한다.

## 9. 테스트

빌드, 실행, 테스트는 모두 개발자 PC의 네이티브 Windows에서 한다. WSL과 Docker는 쓰지 않는다.

| 대상 | 방법 |
|---|---|
| `source` | 자연 정렬, ZIP/CBZ 읽기, 경로 조작 차단 |
| `order` | 합성 bbox로 읽기 순서 검증 |
| `translate` | 프롬프트 구성, JSON 파싱, 누락 id 재요청 (가짜 LLM 서버) |
| `cache` | 키 계산, 용어집 변경 시 무효화 |
| `scheduler` | 우선순위, 취소, 2단계 병행 |
| `bootstrap` | 체크섬 불일치 거부, 이어받기, 진행률 보고 (로컬 가짜 HTTP 서버) |
| `env_check` | `nvidia-smi` 출력 샘플로 파싱·판정 |
| `server` | 토큰 없는 요청 거부, 잘못된 `Host` 거부 |
| 프로세스 수명 | 더미 자식을 Job에 넣고 부모를 강제 종료 → 자식 종료 확인 (Windows 통합 테스트) |
| 웹 UI | 가짜 파이프라인을 붙인 Playwright 스모크 1개(`--browser` 모드): 라이브러리 → 읽기 → 오버레이 → `T` 토글 |
| 설치 파일 | Windows Sandbox 같은 깨끗한 환경에서 수동 체크리스트: 설치 → 마법사 → 읽기 → 창 닫기 후 프로세스 잔존 없음 → 제거 |
| 품질·속도 | `bench <폴더>`: 페이지당 소요 시간과 번역 결과를 HTML로 출력해 사람이 검토. 샘플 만화는 저장소에 넣지 않는다 |

## 10. 결정 대기 항목

- 기본 번역 모델: Gemma 4 E2B / E4B / 12B를 텍스트 전용과 이미지 참고 두 방식으로 `bench`에서 비교해 확정한다.
- 이미지 참고 사용 여부: 같은 비교 결과로 정한다.
- 최소 VRAM: E2B의 품질이 충분하면 12GB에서 8GB로 낮출지 검토한다. 낮추면 1장 대상 환경과 첫 실행 마법사 검사 기준을 함께 고친다.
- 위 세 가지는 계획 1의 마지막 태스크(모델 비교)에서 정한다.
